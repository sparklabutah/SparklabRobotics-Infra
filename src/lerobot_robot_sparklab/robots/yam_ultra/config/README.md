# config

Rig identity for *this physical YAM-Ultra* — the serials, presets and
measurements that would be wrong on any other rig, even another YAM-Ultra.

```
cameras.yaml              which cameras exist, their ids and capture settings
hand_default.json         RealSense advanced-mode preset for the D405 wrists
thirdperson_default.json  RealSense advanced-mode preset for the D435 top cam
intrinsics.yaml           exported intrinsics for all three cameras
```

Generic RealSense tooling lives in
[`cameras/`](../../../cameras/README.md); only rig-specific values belong here.

## `cameras.yaml`

Read by both `relay/server.py` (the live VR view) and `follower.py` (dataset
recording), so the operator watches the same configuration that gets recorded.

| id | serial | model | capture | dataset |
|---|---|---|---|---|
| `left_wrist` | 353322271147 | D405 | 640×480 | crop → 640×360 |
| `right_wrist` | 323622272781 | D405 | 640×480 | crop → 640×360 |
| `top` | 243322071190 | D435 | 640×360 | native |

**Ids are load-bearing in three places**: the relay's VR panel slots, the
LeRobot dataset keys (`observation.images.<id>`), and the follower's camera
dict. Renaming one renames a dataset column.

640×360 matches the `allenai/MolmoAct2-BimanualYAM-Dataset` schema. `height` is
what is requested from the sensor and must be a profile it really offers: the
D435 does 360 natively, while the D405 wrist cameras have no 360-tall mode at
640 wide, so they capture 480 and `crop_height: 360` centre-crops 60 px off top
and bottom. Cropping rather than resizing, so pixel scale matches the training
frames.

## Presets

`advanced_json` points at a preset exported from `realsense-viewer`'s "Save
settings to file", locking exposure, white balance and colour correction. Not
applied automatically — run once per power-up, before the relay or
`lerobot-record`:

```bash
python -m lerobot_robot_sparklab.cameras.apply_camera_presets
```

It persists in the device's own memory until power is lost. There is also a
lighter inline path — `exposure` / `white_balance` / `gain` keys applied by the
relay's reader on every connect, currently unused here. Do not set both for one
camera.

## `intrinsics.yaml`

Generated by `cameras.export_intrinsics`, covering depth and colour streams per
camera. Needed for 3D reasoning from these frames; irrelevant to policies that
consume raw pixels, which is currently all of them.

## Replacing a camera

Serials are physical identity. Swap a camera and you must update
`cameras.yaml`, re-apply presets, and re-export intrinsics. Nothing detects a
swapped serial: the symptom is a camera that fails to open, or a rig where left
and right wrists are silently transposed.
